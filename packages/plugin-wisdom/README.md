# @shanhai/kaipu-wisdom-team · 智囊团插件

> ★ **可单独装 / 可不装。** 卸掉它，场地仍完整可用 —— 这是本包存在的**前提**，不是附加条件。
>
> ⚠️ **但它不能单独工作。** 灯位数据由「开铺」插件（`@shanhai/kaipu-platform`）
> 注册的 `kaipu/*` 网关端点提供（DSH 网关按命名空间挂载，同一 ns 只能挂一个 service，
> 所以本包**不能**再注册一份 —— 详见 `src/client/bridge.ts` 文件头）。
>
> ⇒ **请与 `@shanhai/kaipu-platform` 一起安装。** 只装本包时，面板会**如实显示**
> 「数据通道未就绪 —— 灯位数据由『开铺』场地插件提供」（而不是显成「没有任何灯位」）。
> 这是诚实降级，不是故障。

## 名字的由来（比名字重要）

| 现名 | 拟改 | 含义 |
|:--|:--|:--|
| 专家团 / Expert Team | **智囊团** | 「专家团」= 一组专家（**能力的集合**）；「智囊团」= 一群谋士（**会商量的组织**） |

按流程组团**本质是会商流程**，不是并行调用 —— 名字要装得下这件事。
⚠️ **命名待评审组定**；内部包名先用 `wisdom-team`，
对外字段**别名并存**（`wisdomTeam ?? expertTeam`，契约增补 #16）。

## 两种姿态（必须分开）

| 姿态 | 何时用 | 特征 |
|:--|:--|:--|
| **默认内置** | 客户没带自己的 Agent | 开箱即用（**我们的"样品间"**） |
| **可被替换** | 客户带了自己的 Agent | **任一灯位都能被客户自己的 Agent 顶替** |

★ **能做到"可被顶替"，才是真自由。** 绕不开的东西没人敢用。

## ★★ 「可摘除」约束（本包能不能被摘掉）

| 判据 | 怎么验 | 当前 |
|:--|:--|:-:|
| `@shanhai/kaipu-platform` **不依赖**本包 | 查 platform 的 `package.json` dependencies | ✅ |
| 本包**不往场地插件的座位里塞东西** | 两个 client half 的 `slots.register` 各自独立 | ✅ |
| 摘掉本包目录 + patch 段 ⇒ 场地仍完整 | 配套解耦检查脚本 | ✅ |
| 零 Agent 时界面显「**待接入**」 | `SceneLamp.agentId === null` 的渲染 | ⏳ Step 4 |

## 本包**不含**什么（重要）

- ❌ 我方 Agent 的 skill / memory / 内部 prompt（那些只在服务端）
- ❌ 判据 / 规则库全文
- ❌ 任何密钥

★ 本包只是"网关内建灯组的**客户端面**"，不是"我方 Agent 的实现"。

## ★ 契约层不在本仓（给 clone 下来读/审的人）

★★ **本仓能做什么、不能做什么（一句话口径）**：
**本仓可 `pnpm install` / 可读源码；完整 build 需配套契约层。**

与 `@shanhai/kaipu-platform` 同一条：源码里 `import … from '@shanhai/kaipu-contract'`（**本包只 import 类型**），
而**那个包不在本仓** —— 它是与受理侧共管的**构建期**依赖。

⇒ `pnpm install` **能过**（本包刻意不把它声明为依赖：workspace 协议要求该包就在本仓内，声明了反而会让安装直接失败）；
⇒ **完整构建**需要同级放一份契约包（`tsconfig.json` / `tsconfig.client.json` 的 `paths` 指向它）；
⇒ **用户机不需要它** —— 本包 client 侧只用类型（编译即擦除），故产物里连 `require` 都不产生。

完整说明见 `packages/plugin-platform/README.md` 的「契约层不在本仓」。
