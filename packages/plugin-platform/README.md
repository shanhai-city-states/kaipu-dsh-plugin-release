# @shanhai/kaipu-platform · 场地插件

> **本仓主推件。** 上 DSH 插件市场。装了它，客户就有了「开铺的场地」。

## 它是什么

> **场地插件** = **审计环境标准**：编排对接 + 门禁 + 留痕 + 报告面。
> 它**不含**任何会商资产（那是智囊团插件的事，见 `../plugin-wisdom`）。

## 它承担的客户端能力

| 能力 | 本包位置 |
|:--|:--|
| 总台（Agent 卡片 + 场景卡片） | `client/PlatformPanel.tsx` 左栏 |
| 运行视图（逐灯 + 判定路由可见） | `client/PlatformPanel.tsx` 右栏 |
| 角色位（执行 / 审计 / 管理，签名位不可改） | `client/` 子页 |
| 能力边界页（`cannot` 段必须完整展示） | `client/` 子页 |
| 自定义场景编辑（登记即生效，**不是等审批**） | `client/` 子页 |
| 报告查看与本地验签 | `client/` 子页 |

★ **预约排期面板** 与 **外部 Agent 接入配置**：
外部 Agent 接入配置 **只做配置面板 + 状态镜像**（不代签、不持服务端密钥）。

## 交付形态

| 项 | 定 |
|:--|:--|
| 分发 | **DSH 插件市场**（主路径）· 也支持本地目录安装 |
| 宿主 | 客户自己的 DSH（**我们不要求客户装我们的壳**） |
| 依赖 | 内部契约包（构建期依赖，不随本仓发布；产物已内联） |
| 是否可单独装/卸 | ★ **是**。卸掉智囊团插件后，本插件**必须仍完整可用**（见下） |

## ★ 与智囊团插件的关系（三条约束）

| 含义 | 怎么验 |
|:--|:--|
| 智囊团 = 独立插件；**删掉它，场地仍完整可用** | 静态：本包 `package.json` **不依赖** `@shanhai/kaipu-wisdom`；patch 各自独立 |
| 两者**只通过接口通信** | 本包不 import 智囊团内部实现；智囊团也不 import 本包内部 |
| **场地不内置任何「必须有的」Agent** | 零 Agent ⇒ 界面显「**待接入**」（`SceneLamp.agentId === null`），流程仍能走 |

★ 上面这三条不是洁癖：**绕不开的场地没人来；可替换的东西才卖得出去**。

## 当前能力

| 面 | 内容 |
|:--|:--|
| 结构 | 包结构 / 声明格式 / **结构上可摘除智囊团** |
| 运行 | 构建管线 + 真 DSH 装载 |
| **面板** | 总台（Agent 卡片 + 场景卡片）· 含「已停用」灰显与「待接入」计数 |
| **面板** | 运行视图（逐灯 + 判定路由可见）· 按「第 N 轮」分段 |
| **数据** | 面板接真契约形状的数据 · 内置演示数据（界面有徽标明示） |
| **文案** | 错误码文案 + 三条必须显示的约束 |

**尚未覆盖**：报告验签 · 预约与外部接入 · 报告子页 · 接真服务端。

### 错误文案与三条约束

- **文案表只有一个出处**：契约层的 `translateError()`。
  界面**只显示译后文案**，裸 `code` 只出现在 `data-*` 属性里（给判据用，不给用户看）——
  这是既定的客户端纪律。
- **两个码不是「错误」**：`duplicate_request` / `not_checked_in` 按契约 `clientAction` **不弹错**，
  走 `Reroute` 分支（按 `detail.poll` 切查询接口 / 说明「该场景需进场」）。
  ⚠️ **这两个的出路在 `detail` 里 —— 接线时务必一路把 `detail` 传下去**
  （界面若拿不到 `detail`，用户就没有任何出路；见 `mock/data.ts` 的 `MOCK_ERROR_DETAIL`）。
- **三条必须显示的约束**：未签名醒目提示 / 角色位变更留痕 / 过期不候可重约。
  文案在 `src/client/copy.ts`（出处已注明）。

### 数据面怎么接

```
mock/data.ts ─┐
             ├─→ run-reducer.ts（纯函数）─→ LeftPane / RightPane
真 SSE  ─────┘        ↑
                与来源无关
```

★ **接真服务端时只动一处**：把 `PlatformPanel` 里的 `events` 换成订阅来的事件、
把 `sourceLabel` 置为 `null`。**归约器与两栏渲染都不用改** ——
这是把归约做成独立纯函数换来的。改之前请先读 `run-reducer.ts` 头部那三条约束
（归组键 `(round,lamp)` · 按轮分段 · 轮数不得推断）。

★ **演示数据必须明示**：`mock/data.ts` 顶部有「三条纪律」，第 3 条就是
「必须在界面上标出这是演示数据」。理由与上游插件规范同源 ——
描述与呈现都不能夸大，否则等于自己给自己造一个「名不副实」的把柄。

## 本包的三条硬边界（架构级）

1. **不持有模型 Key、不直连模型**
2. **不绕过宿主统一适配层**直连服务端域名
3. **不越受管根**

外加一条：**本插件的 skill / memory / 内部 prompt 永不出现在任何响应体**。

## ★ 未来演进方向（现在**不拆** · 按触发条件拆）

本包现在**确实是「一件事」**（提供场地），**不要按「感觉变大了」拆** ——
没到触发条件就拆，只会多出四个包互相 import，反而破坏上面的约束。

只在这四个**触发条件**之一成立时才拆：

| 触发条件 | 拆成 | 判据（什么时候才算到） |
|:--|:--|:--|
| **编排**逻辑复杂到需要独立测试 / 独立版本节奏 | `plugin-orchestration` | 编排的接口面能独立成文，且有独立的出错语义 |
| **门禁**逻辑需要独立安全审（对外一句话说不清） | `plugin-gate` | 门禁被要求单独过安全评审 / 单独出具证据 |
| **留痕**需要独立审计（第三方要单独验它） | `plugin-trail` | 有第三方要求「只验留痕、不装其他」 |
| **报告面**需要独立部署（验签要脱离场地可用） | `plugin-report` | 报告验签的可用性要求**高于**场地本身 |

★ 共同的拆分判据只有一条：
> **拆出来的东西，能不能「单独被需要」？**
> 能（有人只想装它）⇒ 拆；不能（永远是场地的零件）⇒ **别拆**。

★ 拆的时候守两条：**① 拆出的包不许被本包 `dependencies` 依赖**（否则白拆）；
**② 各自独立 `cordis.patch.yml`**（摘任一段不影响其他）—— 与 `plugin-wisdom` 同一套姿势。
