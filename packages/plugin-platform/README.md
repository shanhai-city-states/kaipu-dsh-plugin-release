# @shanhai/kaipu-platform · 场地插件

> **场地能力包** —— 多 Agent 会商与审计留痕的场地：场景与 Agent 目录、运行视图、角色位、能力边界页。
> 它可以**单独安装**；配套的会商组织包（`@shanhai/kaipu-wisdom-team`）**可装可不装**。

## 它是什么

**场地插件**提供场地能力：**编排对接 + 门禁 + 留痕 + 报告面**。

它**不含**任何执行方 —— 没有接入任何 Agent 时，界面显示「待接入」，场地**依然可用**。
带自己的 Agent 上场是你的选择（会商组织由 `@shanhai/kaipu-wisdom-team` 提供，或由你自己接入）。

## 交付形态

| 项 | 说明 |
|:--|:--|
| 分发 | DSH 插件市场 · 也支持本地目录安装 |
| 宿主 | 你自己的 DSH（**无需额外安装外壳**） |
| 依赖 | `@shanhai/kaipu-contract`（配套契约包，**不随本仓发布**） |
| 可单独装卸 | **是**。卸掉会商组织包后，本插件**仍完整可用** |

## 与「会商组织」包的关系

| 含义 | 怎么验证 |
|:--|:--|
| 会商组织 = 独立插件；**删掉它，场地仍完整可用** | 静态：本包 `package.json` **不依赖** `@shanhai/kaipu-wisdom-team`；patch 各自独立 |
| 两者**只通过接口通信** | 本包不 import 对方内部实现；对方也不 import 本包内部 |
| **场地不内置任何"必须有的" Agent** | 零 Agent ⇒ 界面显「**待接入**」（`SceneLamp.agentId === null`），流程仍能走 |

> **接口面优先于实现面**：场地只承诺接口与目录能力，谁的 Agent 上来、按什么规矩审，由使用者自己定。

### 错误文案与三条约束

- **文案表只有一个出处**：`@shanhai/kaipu-contract` 的 `translateError()`。
  界面**只显示译后文案**，原始 `code` 只出现在 `data-*` 属性里（给检查脚本用，不给用户看）。
- **两个码不是「错误」**：`duplicate_request` / `not_checked_in` 按契约 `clientAction` **不弹错**，
  走查询接口分支 / 说明「该场景需进场」。
  ⚠️ **这两个码的出路在 `detail` 里 —— 接线时务必一路把 `detail` 传下去**
  （第一版漏传，界面只能说「别急」，用户没有任何出路）。
- **三条必须显示的约束**：未签名醒目提示 / 角色位变更留痕 / 过期不候可重约。
  文案在 `src/client/copy.ts`（出处已注明）。

### 数据面怎么接

```
mock/data.ts ─┐
             ├─→ run-reducer.ts（纯函数）─→ LeftPane / RightPane
真 SSE  ─────┘        ↑
                 与来源无关
```

**接真服务端时只动一处**：把 `PlatformPanel` 里的 `events` 换成订阅来的事件、
把 `sourceLabel` 置为 `null`。**归约器与两栏渲染都不用改** ——
这是把归约做成独立纯函数换来的。改之前请先读 `run-reducer.ts` 头部那三条约束
（归组键 · 按轮分段 · 轮数不得推断）。

**演示数据必须明示**：`mock/data.ts` 顶部三条纪律的第 3 条就是
「必须在界面上标出这是演示数据」—— 描述与呈现都不能夸大。
