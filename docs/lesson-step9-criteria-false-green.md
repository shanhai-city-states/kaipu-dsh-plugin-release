
## 台阶⑨ · 六步进度条判据两次假绿的教训（2026-10-26）

### 假绿 #1：`false &&` 短路骗过 includes
- **判据写法**：`phaseCode.includes('PROJECT_PHASES.map((p, i) =>')`
- **注入**：把 `{PROJECT_PHASES.map(...)}` 改成 `{false && PROJECT_PHASES.map(...)}`
- **结果**：字符串仍在，判据绿 —— 但界面上什么都不渲染
- **正解**：验「**真的被执行**」而非「字符串存在」——往前 40 字符查，不允许被 `false && / false ? / undefined &&` 短路

### 假绿 #2：反向断言被无关代码误命中
- **判据写法**：`/\{\s*p\s*\}/.test(code) === false`（验「不得显示原始 key」）
- **真相**：`PROJECT_PHASES.map((p, i) => {` 的**箭头函数体**里也有 `{` 和 `p` ⇒ 正向代码反而被判红
- **修法**：收紧到 **JSX 子节点形态** —— `>\s*\{p\}` 或 `\{p\}\s*<`

### 通用教训（第三次复现同一族）
| 层 | 错误形态 | 正解 |
|:--|:--|:--|
| 1 | 全文 `includes` | 按**结构边界**切片 |
| 2 | 固定字符数切片 | 数标记/找收尾闭合符 |
| 3 | 不剥注释 | 剥块注释+行注释 |
| 4 | **验字符串存在** | 验**执行形态**（不被短路/不在死分支） |
| 5 | **反向断言太粗** | 反向也要写**结构形态**，不用裸符号组合 |

★ **判据本身也要过注入测试**——这条现在是硬纪律：每条判据写完，必须构造「违反它的代码」验证它变红。
