## 六、★ 我按判据执行时发现的**一处冲突**（必须先说清）

**你们的判据是「不公开它 ⇒ 装不上 / 跑不起来」；市场的收录要求是「仓库里要有真实可用的代码，且描述要能被对着代码核对」。**

两者在 `src/` 上**直接对撞**：

- 按判据：`src/` **答不出来** ⇒ 边界排除。
- 按市场：没有 `src/` ⇒ 人工评审第 1 条（代码与声明一致）**无法执行**，第 3 条（真实可用代码）**直接判负**。

**⇒ 结论：这个冲突没有两全解。三条路：**

| 方案 | 代价 |
|:--|:--|
| **① 带 src**（我建议） | 源码对外 |
| **② 不带 src，放弃收录** | 上架这条路停掉（但插件仍可私下分发/随壳交付） |
| **③ 不带 src，另建一个"薄"公开仓** | 只放 `packages/plugin-*/` 的最小可评审集（见 §七） |

### ★★ v1.1 修订：理由改写（**古茶 `047` 拍板已收到**）

**v1 我写的理由是「插件包里没有商业设计 —— src 只是面板骨架（打日志 / 渲染空槽）」。**
**这个理由已被古茶 `047` 否掉**（原文）：「**不是看 src 是不是'渲染空槽 + 打日志'——那是形式。**
**是看 src 里有没有把商业设计的线画出来。**」⇒ **"只是壳"这个说法不能用。**

**古茶给的替代判据（我方照此自查，结果见 `050`）**：

> **src/ 里有没有越过「接口调用」这条线，进入「数据与判据」这条线？**

| # | 查什么 | 越线即否决 |
|:-:|:--|:--|
| 1 | **服务端调用路径** | 只暴露"调哪个接口、传什么参数" ⇒ **不算越线**（这本来就是公开契约） |
| 2 | **三个可替换位 + 签名位** | 若 src 里写死了"执行位/审计位/管理位/签名位"的**商业设计** ⇒ **越线** |
| 3 | **数据流向与判据** | 若 src 里暴露了"数据从哪来、判据是什么、收费点在哪" ⇒ **越线** |

**⇒ 我方按这三条自查（脚本 `tools/probe/g2-src-line-audit.mjs`，可复跑）的读数**：

- **判据 1（服务端调用路径）**：`ENDPOINTS` 共 7 个方法名 + `baseUrl`，**只有接口名与参数** ⇒ **不越线**。
- **判据 2（可替换位/签名位）**：★ **有一处必须报** —— `mock/data.ts` 里出现了席位名（执行位/审计位/管理位/签名位）
  与**承担方名**（主体核验方/留痕审计方/权责确认方）、**变更留痕样本**。
  **但我方对照发现**：契约 `seats.json` 里的**默认承担方**（山海智囊团/山海第三方审计/山海管理方/山海（平台））、
  `replaceableWith`、`noImplicitIntervention`、`INV-18/19`、四要素（响石三道锁）**在 src 里一处都没有**。
  ⇒ **形式出现了（席位名/留痕），制度本身没出现**。**这一处我方不敢自判，原样交你方独立定**（上下文原文见 `050` 附件）。
