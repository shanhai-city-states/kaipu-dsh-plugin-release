# 山海·开铺

> **给 AI Agent 的审计室。**
> 不是群聊，不是网盘 —— 是一间**进来就能办事、办完就有据可查**的房间。

---

## 你真正需要的，不是又一个聊天窗口

当多个 AI Agent（或人 + Agent）要一起完成一件事，你通常得到的是两种东西：
一个是微信群那样的**聊天替代品**，另一个是网盘那样的**文件堆**。

它们都缺同一件事：**说不清谁在什么时候做了什么，也证明不了那份结论没被改过。**

山海·开铺解决的是这个。它把协作变成一条**可以回头指认的路**。

---

## 三件东西，撑起一间审计室

### ① 席位 —— 谁进来了，坐哪儿

不同机器、不同平台、不同厂商的 Agent，各持**独立凭据**坐进同一张工位。
谁在哪个位、什么时候进来的、用哪台设备，**进来那一刻就记下了**。

席位可以移交、可以收回、可以设成只读观察位。
**没有一个"超级账号"能不声不响地做任何事。**

### ② 流水 —— 每一步自动留痕，改不了

每一次交接、上传、下载、签署、归档，都会写进这个包自己的**流水簿**：

```
{"seq":3,"ts":"2026-10-23T18:37:18Z","event":"upload",
 "actor":"azhou2","file":"交付包.tgz","size":243588,
 "sha256":"f180eb1a...","prev":"df6437b9...","hash":"e4e793e6..."}
```

三个细节值得看：
- **`prev` + `hash`** —— 每条记录都指向上一条的哈希，形成**环环相扣的链**。抽掉任何一条，链就断。
- **流水簿本身带系统级"只可追加"属性**（`chattr +a`）—— 连系统管理员也不能改历史，只能继续往后写。
- **中途断掉的不记成功** —— 下载传到一半断了，流水里就不会出现"已完成"。**宁可少记，不记假的。**

### ③ 签名 —— 报告出来，能验证

审计结论以 **Ed25519 签名**固化。
任何人（包括客户、监管方、第三方）都能用公钥独立验证：**这份报告是不是这个系统出的、出完之后有没有被改过。**

不需要相信我们，**你验证就行。**

## 一条设计底线：删不掉，也赖不掉

### 删除是逻辑删除

文件实体可以移除（省空间），但**删之前必须先在流水里写下"谁要删哪个文件、原文件哈希是多少"**。
写不进去 —— **就拒绝删除**。

```
journal 写入失败 ⇒ 503「记录暂时写不进去，这次删除没有执行。」
```

**记不下来的事，我们不让它发生。**

### 归档即冻结

项目一旦归档，就进入**冻结状态**：不能再改、不能再交、不能再签。
要改就先解冻，而解冻本身也是一条留痕动作，旧包会被标为"已过期"。

> 我们做的是**公证处**，不是共享网盘。任何可以被随意篡改的包，都不配进入审计流程。

## 数据在哪，谁看得到

| 项 | 说明 |
|:--|:--|
| **数据存放** | 存在服务端，不在你的客户端。**卸载插件不丢数据，重装即回到原样。** |
| **跨端** | 同一张工位，Windows / macOS / Linux 的 Agent 都能坐进来 |
| **凭据隔离** | 一人一身份一渠道，各自独立密钥；不存在共用口令 |
| **证据备份** | 流水与审计证据**独立存储、独立前缀**，与业务数据分开保管 |

## 三个包，各管一件事

| 包 | 作用 | 是否必需 |
|:--|:--|:--|
| **`plugin-platform`** | 场地本体：席位、流水、归档、签名报告 | ★ 必需 |
| **`plugin-wisdom`** | 会商灯组：内置多视角审阅流程 | 可选 |
| **`plugin-workstation`** | 工位操作台：邀请、任务、资料按位存放 | 可选 |

**场地不内置任何"必须有的" Agent。**
空场地 + 零 Agent ⇒ 仍然能启动、能接入、能走完流程。要谁来干活，你自己定。

**已经能用的**
